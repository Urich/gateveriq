# Модель безопасности

[English](../security.md) | [Русский](security.md)

## Что означает успешная проверка

Для выданной сервером задачи получено корректное SHA-256 PoW, а связанный токен
использован нужной интеграцией. Это не доказывает присутствие человека,
целостность устройства или законность аккаунта. Решатель можно автоматизировать,
передать третьей стороне либо ускорить другим оборудованием. PoW не заменяет
аутентификацию, ограничения аккаунтов, почтовые политики и защиту входного узла.

## Реализованные меры

- Случайные ID задач, соли и секреты интеграции по 256 бит.
- Сложность и срок действия определяет сервер.
- Каноническое Base64URL-кодирование с точной проверкой размеров.
- Внутренние маршруты с авторизацией на отдельном loopback-адресе.
- Списки разрешённых действий и привязка токена к интеграции, действию и контексту.
- Сравнение хешей секретов за постоянное время.
- Транзакционное однократное использование и ограниченный срок повторов.
- Лимиты тела запроса и числа хранимых в памяти счётчиков.
- Пересланные IP не считаются достоверными; данные браузера и движения указателя
  не являются подтверждением личности.
- Сервис не записывает открытые секреты и токены в прикладные логи.

## Ограничения перед развёртыванием

MVP экспериментальный, без независимого аудита и подтверждения допустимой
нагрузки. Публичные решения намеренно отправляются без авторизации.
Ограничивайте запросы, соединения и параллелизм на входе. Лимит сервиса
применяется после разбора JSON и не защищает от исчерпания полосы и соединений.
Счётчики в памяти сбрасываются при перезапуске, сохраняемая история — нет.
Фиксированные интервалы допускают всплески на границах. Общий предел числа
счётчиков способен временно отклонять новые источники при распределённой атаке.

Вызовы SQLite синхронны и сериализуются внутри асинхронных обработчиков.
Используйте один процесс на БД. У разных процессов независимые счётчики
в памяти. Это не высоконагруженный кластерный сервис. Нет автоматической
адаптации сложности и общей дисковой квоты; контролируйте ресурсы отдельно.

Время PoW заметно различается между браузерами и нативными решателями.
Медленное решение не означает более надёжную проверку. Текущий виджет
англоязычный; перевод документации не меняет его язык.

Приложение отвечает за неизменность привязок, собственную аутентификацию,
ограничения и идемпотентность операций. Скомпрометированный JavaScript страницы
может украсть токен. HTTPS и защита от XSS относятся к ответственности сайта.
Жёсткой привязки токена к IP нет, поэтому смена сети допустима.

Синхронизируйте часы, избегайте перевода назад. Защищайте конфигурацию, ключ,
БД и резервные копии. Не передавайте секреты через аргументы CLI; безопасно
сохраняйте вывод создания и ротации. Для секретов используйте HTTPS либо
аутентифицированный локальный или туннельный транспорт.

## Риск в режиме сайта

Проверяются точный origin и привязка аккаунта; ID аккаунта хранится как HMAC.
Результаты входа сообщает только сервер приложения. По умолчанию история
хранится 24 часа. Браузерный и поведенческий отчёты остаются подделываемыми.
История IP использует адрес соединения, а не заголовки пересылки.

Результат входа требует использованного токена, идемпотентен и неизменяем.
Серверу интеграции доверяется достоверность результата и привязка попытки
к собственной сессии. Атака на конкретный аккаунт способна вызвать лишние
проверки для его владельца: пороги требуют практической оценки.

Решение о дополнительной проверке само по себе не выдаёт токен. Нужны
правильный ответ на привязанную визуальную задачу и исходное PoW. Маленький
статический набор иллюстраций бот может распознать или запомнить: это не
промышленная CAPTCHA. Невизуальной альтернативы пока нет.

Ошибка API и сбой инфраструктуры не должны разрешать вход. HMAC-идентификаторы
псевдонимны, а не анонимны; ключ должен оставаться закрытым. Пакетная очистка
может задерживаться, но просроченная история исключается из расчёта сразу.
