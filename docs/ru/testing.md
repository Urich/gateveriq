# Тестирование

[English](../testing.md) | [Русский](testing.md)

## Автоматические проверки

Выполните из корня репозитория:

```sh
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
node tests/worker.mjs
node tests/behavior.mjs
node tests/visual.mjs
node tests/sdk.mjs
cargo build --locked
python tests/e2e.py
```

При необходимости используйте `python3`. Rust-тесты проверяют токены, изоляцию,
привязки, параллельные запросы, сохраняемую историю, результаты входа, origins,
картинки, смену задач, истечение срока и исчерпание ответов. JavaScript-тесты
проверяют Worker, наблюдения, выбор картинок, отмену, повторы и SDK.
HTTP/CLI-тест использует настоящие порты, перезапускает сервер, декодирует PNG
и завершает вход после неправильного выбора. Эти проверки подтверждают
реализацию правил, а не качество выявления настоящих ботов.

### Блокировка исполняемого файла в Windows

Остановите debug-сервер через Ctrl+C перед пересборкой. Либо используйте другую
папку сборки:

```powershell
cargo test --locked --target-dir target/check
cargo build --locked --target-dir target/check
$env:GATEVERIQ_BINARY = (Resolve-Path 'target/check/debug/gateveriq.exe').Path
python tests/e2e.py
```

Переопределённый путь должен быть абсолютным. Для Linux/macOS:

```sh
cargo build --locked --target-dir target/check
GATEVERIQ_BINARY="$PWD/target/check/debug/gateveriq" python3 tests/e2e.py
```

## Интерактивная проверка в браузере

Для режима сайта используйте [визуальное демо](website-integration.md#try-visual-verification-locally).
Для исходного режима только с PoW при работающем Rust-сервере:

```powershell
cargo run --locked -- integration-create --name browser-test --actions demo
$env:GATEVERIQ_ID = "RETURNED_ID"
$env:GATEVERIQ_SECRET = "RETURNED_SECRET"
$env:GATEVERIQ_WEBSITE = "0"
python examples/demo.py
```

Синтаксис переменных для Linux/macOS:

```sh
export GATEVERIQ_ID='RETURNED_ID'
export GATEVERIQ_SECRET='RETURNED_SECRET'
export GATEVERIQ_WEBSITE='0'
python3 examples/demo.py
```

Откройте **http://127.0.0.1:8090**, нажмите Run verification и Confirm verification.
Проверьте отмену и новую попытку. Демо хранит операции в памяти, использует
фиксированные порты и не реализует production-аутентификацию и сессии.

## Ручные сценарии

1. Повторная подготовка контекста возвращает ту же непросроченную задачу.
2. Неправильное PoW отклоняется, правильный повтор даёт тот же неиспользованный токен.
3. Другое действие или контекст отклоняются при использовании токена.
4. Точный повтор использования успешен, другой request ID отклоняется.
5. Токены и история переживают перезапуск.
6. Неверный или отсутствующий origin и обход через исходный API отклоняются.
7. Для результата входа нужен использованный токен; повторы не увеличивают ошибки.
8. Ошибка в картинках меняет категорию и ID, сохраняет срок и расходует общий
   бюджет. Старый ID не подходит к новому полю.
9. Просроченные и исчерпанные задачи не выдают токен, отмена останавливает интерфейс.
10. Отдельно проверьте настоящие мобильные и настольные браузеры, выбор с клавиатуры.

## Диагностика

| Симптом | Что проверить |
|---|---|
| ACTION_NOT_ALLOWED | Разрешите нужное действие; демо использует `demo` |
| Нет GATEVERIQ_ID/SECRET | Задайте переменные в терминале, запускающем Python |
| ORIGIN_NOT_ALLOWED | Схема, хост и порт должны совпадать; `localhost` и `127.0.0.1` различаются |
| Не появляются картинки | Включите режим сайта и накопите ошибки входа либо временно снизьте порог |
| Старые картинки или интерфейс | Перезапустите пересобранный сервер, обновите через Ctrl+F5 и начните новую попытку |
| 429 | Проверьте лимиты частоты, истории и бюджета ответов |
| Отказано в доступе при сборке | Остановите исполняемый файл либо смените папку сборки |

Автотесты используют малую сложность. Перед выбором параметров измерьте время
PoW в браузерах целевых телефонов и в нативной release-сборке. Артефакты тестов
не публикуются.
