# Подключение сайта

[English](../website-integration.md) | [Русский](website-integration.md)

Сервер сайта создаёт и сохраняет каждую попытку входа. Браузер решает задачу
напрямую через публичный API Gateveriq. Сервер сайта использует токен до
проверки пароля и сообщает фактический результат входа.

Внутренний API доступен только на loopback. Размещайте Gateveriq рядом с сервером
сайта либо используйте закрытый аутентифицированный транспорт. Не передавайте
внутренний API и секрет интеграции браузеру.

## Создание интеграции

```powershell
cargo run --locked -- integration-create --name website --actions login --origins https://your-site.example
```

Укажите настоящий канонический origin без завершающего `/`. Несколько origins
разделяются запятыми. Требуется HTTPS, кроме разработки на localhost.
Режим сайта включает браузерную, поведенческую проверки и сохраняемую историю
IP. Старые интеграции автоматически не меняются. После обновления перезапустите
сервер, чтобы загрузить новые маршруты.

Необязательная секция `config.toml` со значениями по умолчанию:

```toml
[website]
history_retention_seconds = 86400
attempts_per_minute = 20
failure_limit = 5
account_failure_limit = 5
```

Ошибки IP учитываются за десять минутных интервалов UTC, ошибки аккаунта —
за срок хранения, по умолчанию 24 часа. Успех не сбрасывает ошибки.
Это экспериментальные правила, а не откалиброванный классификатор.
Просроченные записи сразу исключаются из расчёта; пакетное физическое удаление
может задерживаться. HMAC-идентификаторы псевдонимны, а не анонимны.

## Сервер сайта: Node.js

Импортируйте `sdk/server.mjs` в backend. Нужна среда с `fetch` и
`AbortSignal.timeout`. Ниже показаны части обработчиков существующего сайта,
а не готовая реализация сессий, паролей и CSRF-защиты.

```javascript
import {GateveriqClient} from './sdk/server.mjs';
const gate = new GateveriqClient({
  integrationId: process.env.GATEVERIQ_ID,
  secret: process.env.GATEVERIQ_SECRET,
});

// POST /login/prepare: обычный обработчик сайта с сессией и CSRF-защитой.
// Сопоставляйте аккаунт с одним непрозрачным ID на всех попытках.
// Для несуществующих аккаунтов также нужна стабильная привязка без раскрытия их существования.
const login = await gate.prepareLogin({
  accountId: opaqueAccountId,
  origin: 'https://your-site.example', // Из конфигурации, не из запроса браузера.
});
session.pendingLogin = {...login, accountId: opaqueAccountId};
// В браузер возвращается ТОЛЬКО login.attempt.
```

```javascript
// POST /login/complete: та же сессия и CSRF-защита.
// Сериализуйте завершение операции; сохраняйте requestId для повторов.
const pending = session.pendingLogin;
if (!pending || !pending.attempt.challenge) throw Error('Нет ожидающей проверки');
await gate.consume({...pending, verificationToken: request.body.verification_token});
// Проверяйте именно pending.accountId: менять аккаунт после подготовки нельзя.
const success = await yourPasswordCheck(pending.accountId, request.body.password);
await gate.reportOutcome({...pending, success});
// Атомарно отметьте операцию завершённой. Создайте сессию входа только при успехе.
// Повторы Gateveriq идемпотентны; операция приложения тоже должна быть такой.
```

Сохраняйте ожидающую операцию на сервере. Не доверяйте контексту, аккаунту и
request ID из браузера. При сбое сообщения о результате повторяйте те же
значения в пределах срока квитанции, по умолчанию 300 секунд.
Ошибка API не разрешает вход. Пароль обрабатывается только сайтом и никогда
не отправляется в Gateveriq.

## Браузер

Разместите `web/widget.js` и `web/worker.js` как статические файлы в одном
каталоге своего сайта. Worker создаётся на origin сайта; не импортируйте виджет
напрямую с другого origin. Решение отправляется непосредственно в Gateveriq.

```html
<div id="verification"></div>
<script type="module">
import {verifyWebsiteAttempt} from '/assets/gateveriq/widget.js';
// Ответ вашего /login/prepare после обычной обработки сессии и CSRF.
const attempt = preparedAttempt;
const result = await verifyWebsiteAttempt(document.querySelector('#verification'), attempt, {
  serviceURL:'https://verify.your-site.example',
});
if (result.decision === 'additional_verification_required') {
  // Дополнительная проверка ещё не завершена: не разрешайте вход.
} else {
  // Отправьте result.verification_token и учётные данные в свой /login/complete.
}
</script>
```

Разрешите URL Gateveriq в CSP `connect-src`, локальный Worker в `worker-src`,
картинки `data:` в `img-src`. Для HTTPS-сайта публичный API тоже должен быть
доступен по HTTPS. Завершающий TLS прокси объединяет клиентов под своим IP,
пока не реализован доверенный входной транспорт. Пересланные заголовки IP
Gateveriq не учитывает. `serviceURL` должен задавать origin, без подкаталога.

## Решения и лимиты

Подготовка возвращает `{"decision":"verify","challenge":{...}}` либо
`additional_verification_required` с `reason: "risk_policy"`, `challenge`,
`visual` и `verification_token: null`. Второй вариант не разрешает вход, пока
задача не решена. Повышение риска при отправке решения также может вернуть
дополнительную задачу с HTTP 403. Неправильное PoW, отсутствующие поля и
исчерпанные лимиты частоты остаются ошибками. Помощник обрабатывает назначение
картинок и на подготовке, и при отправке решения.

Нужно выбрать все предметы того же типа, что показан на образце, среди 16 PNG.
В наборе 24 иллюстрации: кошки, собаки, велосипеды, машины, цветущие растения
в горшках и деревья. Они созданы заранее и встроены в бинарный файл.
В одном поле нет одинаковых картинок, порядок случайный. Правильный ответ
остаётся в SQLite и не передаётся метками категорий или именами файлов.

Срок задачи — до 120 секунд, не дольше исходной PoW-задачи. Общий бюджет —
три неправильных ответа. После ошибки меняются категория, картинки и task ID,
но сохраняются срок и оставшийся бюджет. Повторное получение не сбрасывает
лимит, старый ID не принимается. У новой попытки исключается последняя
сохранённая категория для того же аккаунта и интеграции.

Правильный ответ вместе с исходным PoW даёт токен той же попытки входа.
Визуальный успех заменяет отказ по браузерным/поведенческим сигналам и истории
IP только для этой попытки. Обычные ограничения частоты остаются.
История аккаунта и источника не обнуляется.

Небольшой статический набор можно распознать или запомнить автоматически.
Это проба оформления, а не промышленная CAPTCHA и не усиление защиты от ботов.
Выбор с клавиатуры поддерживается; невизуальной альтернативы пока нет.

Аккаунт, origin и случайный контекст связаны сервером. Токены короткоживущие и
одноразовые; точный повтор допустим только с тем же request ID. Origin защищает
браузерную интеграцию от неправильного сайта, но HTTP-бот может подделать его.

История отражает отправки в Gateveriq и сообщённые результаты входа, а не все
запросы и ошибки пароля на сайте. Приложение должно применять этот сценарий ко
всем защищаемым путям входа. Общие IP и атаки на аккаунт способны создавать
лишние проверки для настоящих пользователей — проверяйте пороги на практике.

## Локальный запуск визуального демо

Создайте интеграцию с действием `demo`:

```powershell
cargo run --locked -- integration-create --name visual-demo --actions demo --origins http://127.0.0.1:8090
```

Перезапустите обновлённый Rust-сервер:

```powershell
cargo run --locked -- serve
```

В другом терминале задайте полученные значения:

```powershell
$env:GATEVERIQ_ID = "ID_FROM_COMMAND"
$env:GATEVERIQ_SECRET = "SECRET_FROM_COMMAND"
$env:GATEVERIQ_WEBSITE = "1"
python examples/demo.py
```

Для Linux/macOS:

```sh
export GATEVERIQ_ID='ID_FROM_COMMAND'
export GATEVERIQ_SECRET='SECRET_FROM_COMMAND'
export GATEVERIQ_WEBSITE='1'
python3 examples/demo.py
```

Откройте http://127.0.0.1:8090. Отметьте **Simulate a failed password** и
завершите пять проверок. Для одного неудачного входа временно задайте
`account_failure_limit = 1` в `[website]` и перезапустите сервер. Следующая
проверка покажет картинки. Снимите отметку перед следующей имитацией входа,
если хотите получить успешный результат.

Переключатель неправильного пароля — только средство локального тестирования.
В настоящем приложении результат сообщает сервер после реальной проверки.
В этом режиме браузер отправляет решения напрямую, Python только создаёт
попытки и использует токены. После обновления используйте Ctrl+F5 и новую попытку.
