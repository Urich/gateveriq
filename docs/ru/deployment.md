# Развёртывание и конфигурация

[English](../deployment.md) | [Русский](deployment.md)

## Инициализация

Начните с [быстрого запуска](../../README.ru.md). По умолчанию оба API доступны
только на localhost. Используйте отдельную непривилегированную учётную запись.
В Unix задайте `umask 077`; в Windows ограничьте ACL конфигурации, ключа,
каталога БД и служебных файлов SQLite.

`init` создаёт абсолютные пути и не перезаписывает существующие файлы.
Свой конфигурационный файл задавайте до подкоманды:

```sh
gateveriq --config /etc/gateveriq/config.toml serve
```

## Настройки

| Корневой параметр | По умолчанию | Назначение и диапазон |
|---|---|---|
| database | Абсолютный путь из init | База SQLite |
| token_key_file | Абсолютный путь из init | Ключ 32 байта в каноническом Base64URL без padding |
| public_listen | 127.0.0.1:9080 | Публичный API и файлы виджета |
| internal_listen | 127.0.0.1:9081 | Внутренний API, только loopback |
| difficulty_bits | 18 | Сложность PoW, 1–24 |
| challenge_ttl_seconds | 120 | Срок задачи, 10–600 секунд |
| token_ttl_seconds | 60 | Срок токена, 10–300 секунд |
| retention_seconds | 300 | Повторы и хранение квитанций, 300–86400 секунд |
| requests_per_minute | 120 | Положительный лимит запросов на интервал в памяти |
| max_active_challenges | 1000 | Положительный лимит непросроченных задач интеграции |

Необязательная секция сайта со значениями по умолчанию:

```toml
[website]
history_retention_seconds = 86400
attempts_per_minute = 20
failure_limit = 5
account_failure_limit = 5
```

Срок истории: 600–86400 секунд; остальные параметры секции: 1–10000.
Ошибки IP учитываются за десять минутных интервалов UTC, ошибки аккаунта — за
весь срок хранения. Частота ограничивается в пределах минуты UTC. Эти параметры
также задают пороги исходных интеграций с `--history-check`.

Изменения конфигурации требуют перезапуска. Сложность и срок уже созданной
задачи не меняются. Файл ключа может заканчиваться переводом строки.
История и квитанции имеют разные сроки хранения. Очистка пакетная: просроченные
данные уже не участвуют в решении, хотя физическое удаление может задержаться.

## HTTPS и обратный прокси

Для HTTPS-сайта публикуйте публичный API через HTTPS, например на отдельном
домене. Помощник сайта строит пути API от корня: указывайте origin сервиса,
а не URL с подкаталогом.

```caddyfile
verify.example.com {
    reverse_proxy 127.0.0.1:9080
}
```

Не публикуйте внутренний API. Разместите widget/worker на origin самого сайта,
как описано в [подключении сайта](website-integration.md). Сервис не раздаёт
демо-приложение по `/`.

Пересланные IP игнорируются. За прокси пользователи разделяют его адрес в
лимитах и истории. Ограничивайте реальных клиентов на доверенном входном узле;
поддержки доверенных пересланных адресов пока нет. Ограничения соединений,
размера и ресурсов на входе нужны отдельно от проверки JSON приложением.

## Управление интеграциями

```sh
gateveriq integration-create --name forum --actions signup,comment
gateveriq integration-create --name screened --actions login --browser-check --behavior-check --history-check
gateveriq integration-create --name website --actions login --origins https://site.example
gateveriq integration-rotate --id INTEGRATION_ID --grace-seconds 300
gateveriq integration-disable --id INTEGRATION_ID
gateveriq cleanup
```

`--actions` и `--origins` принимают списки через запятую. Origins должны точно
задавать HTTPS-схему, хост и порт без пути и завершающего `/`; HTTP разрешён
только для локальной разработки. `--origins` включает режим сайта и все проверки.

Создание и ротация выводят секрет один раз. Срок действия старого секрета после
ротации задаётся в диапазоне 0–3600 секунд. Хранится только один предыдущий
секрет; новая ротация заменяет его. Отключённая интеграция не может создавать
задачи и использовать токены через внутренний API. CLI пока не позволяет
включить её обратно, изменить действия/origins или политики существующей
интеграции — для другой конфигурации создайте новую.

## Копирование, обновление и эксплуатация

Используйте backup API SQLite либо остановите сервис перед копированием.
Сохраняйте БД вместе с ключом. Копировать только основной файл при активном
WAL небезопасно. Текущий код добавляет таблицы при запуске; совместимость
произвольных старых версий с обновлённой БД не гарантируется. Не используйте
одну БД одновременно в независимо развёрнутых версиях.

Ротация ключа токенов не реализована. Его замена меняет восстановление токенов
и псевдонимы истории. Для аварийной смены остановите выдачу и сервис,
дождитесь истечения или удалите активные задачи, безопасно замените ключ и
потребуйте начать новые операции.

`GET /health` возвращает `ok` для проверки процесса, но не готовности БД.
Ошибки очистки выводятся в stderr. Метрики, аудит, плавная остановка, кластер и
production-установщик пока не реализованы. Синхронизируйте часы и следите за
диском и CPU. Автоматической публикации бинарных файлов и релизов нет.
