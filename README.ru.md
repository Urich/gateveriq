# Gateveriq

[English](README.md) | [Русский](README.ru.md)

Самостоятельный экспериментальный антибот-сервис для сайтов и приложений.

Gateveriq объединяет вычислительные задачи SHA-256 (Proof of Work), проверки
браузерных и поведенческих сигналов, историю попыток, привязку к аккаунту и
визуальную дополнительную проверку. Для подключения используются браузерный
виджет и серверный API. Внешний сервис проверки при работе не требуется.

**Это экспериментальный MVP, а не доказательство присутствия человека.**
Браузерные данные можно подделать, небольшой набор иллюстраций — запомнить.
Подробнее: [модель безопасности](docs/ru/security.md).

## Требования

- Стабильные Rust и Cargo, редакция 2021; компилятор C для встроенной SQLite.
- Современный браузер с модулями, Workers, Web Crypto и BigInt.
- HTTPS либо localhost для проверки в браузере.
- Python 3 для демо и HTTP-тестов; Node.js для JS-тестов и необязательного серверного SDK.

## Запуск демо для сайта

В Windows выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт собирает проект, создаёт недостающую конфигурацию и интеграцию демо,
сохраняет её данные в `.demo-credentials.json` и запускает API вместе с сайтом.
Откройте http://127.0.0.1:8090. Для остановки нажмите Ctrl+C.
Параметр `-InitOnly` выполняет только подготовку. При повторном запуске настройки
и интеграция используются повторно. Храните файл `.demo-credentials.json` в секрете.
Нужны Rust/Cargo, инструменты сборки C/C++ и Python 3 для демо.
Существующий `config.toml` должен использовать стандартные адреса API:
`127.0.0.1:9080` и `127.0.0.1:9081`.

В корне репозитория выполните первоначальную настройку:

```powershell
cargo build --locked
cargo run --locked -- init
cargo run --locked -- integration-create --name visual-demo --actions demo --origins http://127.0.0.1:8090
cargo run --locked -- serve
```

Если конфигурация уже существует, пропустите `init`. Сохраните выданные ID и секрет.
Ввод JSON с ними в консоль работающего сервера не настраивает клиент.
В другом терминале PowerShell задайте полученные значения:

```powershell
$env:GATEVERIQ_ID = "ID_FROM_COMMAND"
$env:GATEVERIQ_SECRET = "SECRET_FROM_COMMAND"
$env:GATEVERIQ_WEBSITE = "1"
python examples/demo.py
```

Откройте **http://127.0.0.1:8090**, нажмите **Run verification**, затем
**Confirm verification**. Публичный API работает на `127.0.0.1:9080`, внутренний —
на `127.0.0.1:9081`. Демо предназначено только для локальных тестов.

Для появления картинок отметьте **Simulate a failed password** и завершите пять
проверок. Следующая попытка потребует выбрать изображения. Для быстрого теста
укажите `account_failure_limit = 1` в единственной секции `[website]` файла
`config.toml` и перезапустите Rust-сервер. После неправильного выбора предмет и
картинки меняются, но общий лимит трёх ответов и срок действия сохраняются.
После обновления кода перезапустите сервер и обновите страницу через Ctrl+F5.

Команды для Linux/macOS и исходного режима демо: [тестирование](docs/ru/testing.md).

## Подключение к настоящему сайту

```sh
cargo run --locked -- integration-create --name website --actions login --origins https://your-site.example
```

Сервер сайта создаёт попытку, привязанную к аккаунту. Браузер отправляет решение
напрямую в Gateveriq; при повышенном риске виджет показывает изображения.
Сервер сайта использует токен через внутренний API до проверки пароля, сообщает
фактический результат входа и выполняет свою операцию однократно.
Секрет интеграции остаётся на сервере сайта.

Разместите `web/widget.js` и `web/worker.js` на своём сайте. Для Node.js есть
необязательный клиент `sdk/server.mjs`. [Полный пример](docs/ru/website-integration.md).

## Режимы и история

| Параметр | Поведение |
|---|---|
| Без флагов проверки | Исходный API только с PoW |
| `--browser-check` | Обязательные данные браузера и проверка признаков автоматизации |
| `--behavior-check` | Дополнительно отчёт о взаимодействии, привязанный к задаче |
| `--history-check` | Сохраняемые ограничения частоты и ошибок по интеграции и IP |
| `--origins https://site.example` | Режим сайта: все три проверки, origins, аккаунты и результаты входа |

По умолчанию допускаются 20 отправок в минуту UTC. Пять ошибок проверки за десять
минутных интервалов приводят к отказу по истории; пять сообщённых ошибок входа
для аккаунта за срок хранения требуют дополнительной проверки. История хранится
24 часа. Пороги задаются в `[website]`. Успех не обнуляет ошибки.
Заголовки с пересланным IP сервер игнорирует.

Локальный набор содержит 24 иллюстрации шести категорий. На поле — 16 разных
картинок, максимум три неправильных ответа, срок действия — до 120 секунд.
Это пробный набор оформления, а не промышленная CAPTCHA.

## Разработка

```sh
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
node tests/worker.mjs
node tests/behavior.mjs
node tests/visual.mjs
node tests/sdk.mjs
cargo build --locked
python tests/e2e.py
```

При необходимости используйте `python3`. В Windows остановите debug-сервер перед
пересборкой либо используйте отдельную папку сборки, как описано в тестировании.
Автоматическая публикация релизов и лицензия открытого ПО пока не настроены.
